Before doing any task, always follow these 10 core rules:
1. **Understand Existing Project**: Inspect the complete existing codebase and docs first.
2. **Zero Duplication**: Never create duplicate functionality or duplicate modules.
3. **Reuse First**: Reuse existing code, components, services, APIs, hooks, and database models.
4. **Backward Compatibility**: Maintain backward compatibility across all 4 portals, mobile apps, and APIs.
5. **Follow Standards**: Follow existing architecture, coding standards, UI/UX, and design system (`gbs-design-system.css`).
6. **Multi-Role Mindset**: Think like Enterprise Architect, Senior Full Stack Engineer, QA Engineer, Security Engineer, DevOps Engineer, Product Manager, and Business Analyst.
7. **Every Implementation Must Include**: Validation, Error Handling, Logging, Security, RBAC, Tenant Isolation, Performance, Responsive UI, Accessibility, Documentation, and Testing.
8. **Impact Analysis**: Analyze impact on Admin Portal, Partner Portal, Customer Portal, Mobile Apps, API Gateway, Database, Google Business Profile, AI Engine, Billing, Notifications, and Integrations.
9. **Enterprise Solution Suggestion**: If a better enterprise solution exists, suggest it before implementation.
10. **Analyze Before Implementation**: Never assume. Analyze first, then implement.
11. **Automated Testing Mandatory**: Always test every single implementation feature by creating comprehensive automated test cases and executing them programmatically. Never rely on manual testing or user manual verification.

## 🚀 UNIVERSAL WORKFLOW

### Pre-Task Execution
1. Review the existing implementation first.
2. Locate reusable code, components, services, and APIs.
3. Identify missing functionality, bugs, security vulnerabilities, performance bottlenecks, UI/UX inconsistencies, database/API gaps, missing test cases, and outdated documentation.
4. If improvements are required, implement them cleanly. If something already exists, improve it instead of recreating it.
